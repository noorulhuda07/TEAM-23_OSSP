# Experiment 6 - Task 2
## POSIX Signal Handling

### Aim

To create a Linux C program that handles POSIX signals `SIGINT`, `SIGTERM`, and `SIGUSR1`, demonstrate asynchronous event handling, and understand the role of signal handlers.

---

## Theory

A signal is an asynchronous notification delivered by the operating system to a process to notify it that an event has occurred.

A process can install a signal handler to execute specific code when a particular signal is received.

This experiment uses the POSIX `sigaction()` system call to register signal handlers.

### Signals Used

| Signal | Purpose |
|---|---|
| `SIGINT` | Interrupt signal, commonly generated by Ctrl+C |
| `SIGTERM` | Requests normal process termination |
| `SIGUSR1` | User-defined signal for application-specific events |

---

## Role of a Signal Handler

A signal handler is a function that is executed when the process receives a particular signal.

The operating system invokes the handler asynchronously, meaning the signal can arrive while the process is performing another operation.

In this program:

- `SIGUSR1` increments a signal counter.
- `SIGINT` sets a termination flag.
- `SIGTERM` sets a termination flag.
- The main program checks the termination flag and exits gracefully.
